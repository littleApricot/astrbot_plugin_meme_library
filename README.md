# 群聊表情图库

自动收集群聊里的新图片，为每张图生成**名称和简短描述**。回复模型可以搜索、看图、发送，结合群友纠正修改信息，也能取得原文件路径供 Wiki 上传工具使用。

适配 AstrBot 4.29.x，验证目标为 4.29.1。数据保存在 AstrBot 的 `data/plugin_data/astrbot_plugin_meme_library/`，更新时保留图库，初次安装为空。

## 安装与更新

仓库：[littleApricot/astrbot_plugin_meme_library](https://github.com/littleApricot/astrbot_plugin_meme_library)。在插件市场添加以下源，安装“群聊表情图库”；已添加该源的用户直接检查更新：

```text
https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json
```

打开插件配置并启用。收图与语义搜索模型留空时，使用来源会话的当前回复模型，该模型需要支持图片输入。切换使用时关闭旧表情插件的收图和发送功能，避免两套同时工作。

所有启用了本插件的群聊共用图库。新图片先保存原文件，再由后台识别；完全相同的文件复用一条记录，配字不同的版本保留。适合用作表情的图片进入可用图库，其余显示为“未收录”。

与回复判断插件配合时，收图先于回复判断执行，机器人保持沉默时也能收图。QQ 官方接口必须实际下发图片；只有表情名称、没有图片附件的消息无法据此还原原图。

## 名称与简短描述

每张图只有一份当前有效信息，包含两个可编辑字段，模型和管理页修改同一份数据：

| 字段 | 要求 | 示例 |
| --- | --- | --- |
| `name` | 名称，通常 2–12 字，最多 24 字，优先写可确认的角色、形象或表情系列，再补动作或情绪 | QQ企鹅被拿捏 |
| `description` | 一两句话，通常 20–60 字，最多 120 字，保留关键画面、配字或用途 | 戴红围巾的QQ企鹅被大手捏住，表示被拿捏或求饶。 |

在「群聊表情图库」管理页右上角点「识图提示词」，即可编辑图片名称与描述的完整生成提示词，也可填入默认提示词后保存。该入口与插件配置中的「图片名称与描述生成提示词」共用同一个值，默认沿用当前的简短实用风格，留空使用默认提示词。输出必须保留 JSON 字段 `is_meme`（布尔值）、`name` 和 `description`；名称最多 24 字，描述最多 120 字。保存后用于后续新图片识别和失败重试，已有图片信息保留。

默认提示词优先辨认具体形象，例如 QQ企鹅、小红书默认表情、熊猫头；无法确认具体角色或系列时，使用可见形象特征加动作命名。升级保留已保存的提示词；要采用新版默认风格，在管理页点「填入默认提示词」并保存，或清空后保存。

模型接受普通群友的纠正，先看图并读取最新版本，再决定是否修改名称或描述。保存时检查版本，避免旧内容覆盖新修改；修改记录可恢复为新版本。

旧版长说明升级时会自动拆成短字段，原始长文保留在数据库原列和旧修改记录中。迁移不会移动图片或增加新增提醒计数。

## 搜索、看图、发送和原图路径

自然语言搜索由模型分批读取所有可用名称与描述，按表达含义、态度和对象选择候选。修改立即影响后续搜索；图库较大时需要多个模型调用。历史中已有的候选可以复用。

发送前，模型必须通过 `meme_view` 查看实际图片，在后续一次模型推理中决定是否发送。同一批并行的查看和发送会被拒绝，同一轮重复发送同一张图会被拦截。GIF 等动图最多提供四张分散位置的预览帧，实际发送仍使用原动图。

搜索、查看、编辑和发送结果都包含 `local_path`，它是 **AstrBot 主机上保存的原文件绝对路径**。模型可以把该路径传给能读取同一主机文件的 Wiki 上传工具；预览是 JPEG 时，路径仍指向原始 PNG、GIF 等文件。名称修改不会改动文件路径。

路径本身不是远程图片链接。Wiki 上传工具需要具备读取该主机文件的能力，上传是否成功以上传工具结果为准。

## 工具参数

以下参数均为必填；`caption` 允许空字符串。

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| `meme_search` | `query`：想表达的含义、态度及对象 | `ok`、`candidates`；每项包含 `id`、`name`、`description`、`revision`、`local_path`、匹配 `score` |
| `meme_view` | `meme_id`：稳定图片 ID | `id`、名称、描述、版本、路径、状态和实际图片帧；失败返回错误结果 |
| `meme_edit` | `meme_id`、`name`、`description`、`expected_revision`：本轮查看到的整数版本、`reason`：修订原因 | `ok`、当前名称、描述、版本、路径；版本冲突需重新读取 |
| `meme_send` | `meme_id`、`expected_revision`、`caption`：配文，纯图时填空字符串 | `ok`、`sent`；成功包含图片信息、路径和配文 |

`meme_send` 实际发送图片及配文。成功后模型应避免在最终回复里重复发送相同内容；平台出错时返回 `sent=false`，该轮不自动重试同一图片，避免部分送达后重复发送。

## 历史与新增提醒

工具调用和结果沿用 AstrBot 正常上下文与历史机制。只有新图片首次进入可用图库时，在各会话的下一次模型输入里提示：**图库有新增表情包。** 模型完成回复后记录该会话的新增进度。

修改名称、描述、恢复版本和重新启用已收录图片，都不增加新增计数。首次启用一张此前未入库的图片时，作为新增处理。

## 管理页

从 AstrBot 侧栏打开“群聊表情图库”。可以按名称、描述或 ID 搜索，筛选状态，编辑两个字段，查看原文件路径和修改记录，恢复版本，停用或重新启用图片。

右上角「识图提示词」可直接读取、编辑和保存生成提示词。保存写入插件配置并立即用于后续识图。

下载失败和首次识别失败的记录可重试；已有人修改过信息时保留修改，由管理页查看并处理。停用的图片退出搜索并禁止发送，原文件继续保留。

## 配置

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| 启用表情图库 | 开启 | 收图和模型工具总开关 |
| 收图与语义搜索模型 | 空 | 默认使用来源会话回复模型；可指定 AstrBot 中已有模型 |
| 图片名称与描述生成提示词 | 内置识图提示词 | 可多行编辑，留空使用默认提示词；用于后续新图片识别和失败重试 |
| 识别和搜索超时秒数 | 45 | 单次后台识别或搜索模型调用超时 |
| 单张图片大小上限 | 15 MB | 超过上限时不保存 |
| 每次搜索返回的候选数量 | 5 | 最多返回 20 个候选 |
| 语义搜索每批说明字符预算 | 24,000 | 说明分批预算，按字符计数 |

密钥沿用 AstrBot 提供商配置。管理 API 通过 AstrBot 插件页面的认证桥接访问。

## 验证

在插件目录执行，`ASTRBOT_SOURCE` 指向自己的 AstrBot 源码：

```bash
ASTRBOT_SOURCE=/path/to/AstrBot
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH="$ASTRBOT_SOURCE:$PWD/.." \
  ASTRBOT_ROOT=/tmp/meme-library-test \
  "$ASTRBOT_SOURCE/.venv/bin/python" -m pytest tests -q
```

隔离测试覆盖旧库迁移、字段长度、版本冲突、名称与描述搜索、原文件路径、GIF 原文件保留、看图后发送、正常工具历史、新增提醒及管理 API，也检查提示词的共用配置、保存重载、识图调用和写入失败回滚。管理页使用合成图片实际操作保存与版本恢复。真实模型描述质量、QQ 发图和 Wiki 上传需要在对应环境验证。
