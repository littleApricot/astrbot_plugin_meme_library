# 群聊表情图库

自动收集群聊里的新图片，为每张图生成**名称和简短描述**。正式回复前自动提供最多五张可选表情，回复模型可以看图、发送或继续搜索，结合群友纠正修改信息或停用误收录的表情，也能取得原文件路径供 Wiki 上传工具使用。

适配 AstrBot 4.29.x，验证目标为 4.29.1。数据保存在 AstrBot 的 `data/plugin_data/astrbot_plugin_meme_library/`，更新时保留图库，初次安装为空。

## 安装与更新

仓库：[littleApricot/astrbot_plugin_meme_library](https://github.com/littleApricot/astrbot_plugin_meme_library)。在插件市场添加以下源，安装“群聊表情图库”；已添加该源的用户直接检查更新：

```text
https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json
```

打开插件配置并启用。默认使用 AstrBot 模型收图；「收图识别模型」留空时使用来源会话的当前回复模型，收图模型需要支持图片输入。也可以按下节改用本机 Codex 识图。切换使用时关闭旧表情插件的收图和发送功能，避免两套同时工作。

所有启用了本插件的群聊共用图库。新图片先保存原文件，再由后台识别；完全相同的文件复用一条记录，配字不同的版本保留。适合用作表情的图片进入可用图库，其余显示为“未收录”。

采用 LCM 保存群聊原图时，可在 AstrBot 配置中关闭“群聊上下文感知”的图片描述，避免另一套图片描述调用；本插件的收录识图继续使用所选后端。

与回复判断插件配合时，收图先于回复判断执行，机器人保持沉默时也能收图。回复判断 v0.8.0 将图片转成文字占位；本插件 v0.5.0 为已匹配的图片提供当前名称和描述，只读取已保存资料，未知图片保留占位。QQ 官方接口必须实际下发图片；只有表情名称、没有图片附件的消息无法据此还原原图。

## 用本机 Codex 调用 Astra 识图

在运行 AstrBot 的同一主机、同一系统用户下安装 Codex CLI，并通过 `codex login` 登录 ChatGPT。本机已验证 CLI 0.155.1，所用版本需支持 `--ignore-user-config`、`--ephemeral` 和 `--output-schema`。用 `codex login status` 确认登录后，在插件配置中把「新图片识别方式」设为 `codex`。

插件会用 `gpt-6-astra` 识别新图片，复用当前的识图提示词，生成名称和简短描述并写回同一份图库。静态图输入一帧，动图最多输入四帧；附近发言作为使用线索。已有图片信息保留，失败重试也使用当前选择的识图方式。

此选项用于后台收图识别。表情搜索在本地按名称和描述匹配；正式聊天及发送前看图由会话回复模型处理。

这里是本机 CLI 调用云端 Astra，使用 Codex 账户额度，无需另填 API Key。CLI 沿用登录，但单次识图忽略个人 `config.toml`，使用临时工作目录、只读沙箱和临时会话，并关闭命令执行、插件、连接器、联网搜索等工具。识图输入文件在调用结束后删除。[Codex 非交互调用说明](https://learn.chatgpt.com/docs/non-interactive-mode)

「本机 Codex 可执行文件路径」留空时从 `PATH` 或 `~/.local/bin/codex` 查找，找不到时可填完整路径。AstrBot 在容器或远程服务器中运行时，需要在那个运行环境内安装并登录 CLI。

识图默认最多等待 120 秒，包含 CLI 启动时间。找不到 CLI 时管理页显示 `codex_not_found`；CLI 调用失败显示 `codex_exit_退出码`；超时显示 `TimeoutError`。图片保留在失败列表，处理登录、额度或路径问题后可点击重试。失败时不自动换用其他模型。

## 名称与简短描述

每张图只有一份当前有效信息，包含两个可编辑字段，模型和管理页修改同一份数据：

| 字段 | 要求 | 示例 |
| --- | --- | --- |
| `name` | 名称，通常 2–12 字，最多 24 字，优先写可确认的角色、形象或表情系列，再补动作或情绪 | QQ企鹅被拿捏 |
| `description` | 一两句话，通常 20–60 字，最多 120 字，保留关键画面、配字或用途 | 戴红围巾的QQ企鹅被大手捏住，表示被拿捏或求饶。 |

在「群聊表情图库」管理页右上角点「识图提示词」，即可编辑图片名称与描述的完整生成提示词，也可填入默认提示词后保存。该入口与插件配置中的「图片名称与描述生成提示词」共用同一个值，默认沿用当前的简短实用风格，留空使用默认提示词。输出必须保留 JSON 字段 `is_meme`（布尔值）、`name` 和 `description`；名称最多 24 字，描述最多 120 字。保存后用于后续新图片识别和失败重试，已有图片信息保留。

默认提示词优先辨认具体形象，例如 QQ企鹅、小红书默认表情、熊猫头；无法确认具体角色或系列时，使用可见形象特征加动作命名。升级保留已保存的提示词；要采用新版默认风格，在管理页点「填入默认提示词」并保存，或清空后保存。

模型接受普通群友的纠正，先看图并读取当前资料，再决定是否修改名称或描述。插件自动根据本轮查看记录检查资料是否已变化；有变化时返回错误，模型重新看图后再决定。管理页保留修改记录和版本恢复。

发现误收录或不适合继续使用的表情时，模型可以主动停用；普通群友也可以提醒它删除，由模型结合图片和上下文判断是否采纳。模型先用 `meme_view` 确认具体图片，再在后续一次工具调用中用 `meme_disable` 提交图片 ID；目标不明确时先确认。

删除在这里指停用：所有群共用的图库会立即排除该图，搜索和发送均不可用，原图、名称和描述保留。同一文件再次出现在群里时复用原记录，保持停用。操作会增加一个内部版本，修改记录保存操作类型和来源会话；可在管理页重新启用。停用不产生新增表情提醒。

旧版长说明升级时会自动拆成短字段，原始长文保留在数据库原列和旧修改记录中，原图位置保持不变。

## 搜索、看图、发送和原图路径

每次正式回复开始时，程序从可用图库中选出**四张排序推荐加一张随机推荐**，临时提供 ID、名称和简短描述。提示明确说明可以发送，也可以不用，这只是图库的一部分，其他图片仍可通过工具搜索。可用图片不足五张时提供现有图片，批内去重，停用项和原文件缺失项不参与。

自动推荐完全由本地程序计算：先按新图加成，再按最近使用，最后按累计使用次数排序。每张图片初始有四级新图加成，每被推荐一次降低一级，四次后归零；同级图片优先最近 24 小时内实际使用过的，再按累计次数排序，仍相同则优先较新入库的图片。第五张从未进入前四的其余可用图片中等概率抽取，冷门旧图也能被选中。

机器人成功发送图片、群友实际发送的图片计入使用次数，所有群共用统计。推荐次数单独累计，搜索和看图不算使用；随机位同样计一次推荐曝光。统计从升级后开始，已有图片初期也会参与新图轮换，原图、说明、修订记录和新增提醒进度保留。

与 LCM 配合时，推荐在判断放行后进入历史之后的本轮临时块，不进入回复判断输入，也不写入历史上下文；同一轮后续工具步骤沿用同一份推荐，下一轮重新计算。推荐只是一部分、可以不用、也可搜索完整图库的说明放入图库系统块。LCM v0.6.9 将完整工具用法和参数说明也放入系统区，管理页自定义说明需配套工具说明编辑 v0.3.1。动态候选放在历史之后，便于提供商复用相同请求前缀的缓存，实际命中率与耗时由提供商决定。自动推荐和关键词搜索都由本地程序完成，收图识别沿用所选方式。

模型可以主动搜索适合当前回复的表情，也可以按用户的找图请求搜索。群友发来的图片按原图和聊天上下文正常理解、回应，收到图片本身不代表找图或重发请求。

本地搜索读取全部可用图片的当前名称与描述，按关键词覆盖度排序，名称命中和完整短语命中增加权重，相关度相同时优先较新入库的图片。中文按连续双字片段匹配，单字关键词按字匹配；英文忽略大小写，支持全角与半角归一化，也可用完整图片 ID 查找。编辑、恢复版本或停用立即影响后续搜索，原文件缺失的项不返回。

多个关键词用空格分隔，例如“熊猫 捂脸”；找不到时可换用名称或描述中可能出现的词。匹配不做同义词推断，候选是否适合当前对话由回复模型结合原图决定。同一轮内已搜索到的候选可以复用，后续轮次可以按已发送图片的 ID 重新查看，需要其他图片时重新搜索。

搜索结果只表示图库中的匹配项，不代表用户图片的收录或审核状态。主动选表情却没有合适结果时，模型继续正常聊天；用户要求找图时，可以说明未找到匹配项。

发送前，模型必须通过 `meme_view` 查看实际图片，在后续一次模型推理中决定是否发送。同一批并行的查看和发送会被拒绝，同一轮重复发送同一张图会被拦截。GIF 等动图最多提供四张分散位置的预览帧，实际发送仍使用原动图。

搜索、查看、编辑及发送结果包含 `local_path`，它是 **AstrBot 主机上保存的原文件绝对路径**。模型可以把该路径传给能读取同一主机文件的 Wiki 上传工具；预览是 JPEG 时，路径仍指向原始 PNG、GIF 等文件。名称修改不会改动文件路径。

路径本身不是远程图片链接。Wiki 上传工具需要具备读取该主机文件的能力，上传是否成功以上传工具结果为准。

## 工具参数

以下参数均为必填。

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| `meme_search` | `query`：名称、角色、动作或情绪的短关键词，多个词用空格分隔；也可传图片 ID | `ok`、`candidates`；每项包含 `id`、`name`、`description`、`local_path`、本地相关度 `score`（0～1，不是模型概率） |
| `meme_view` | `meme_id`：稳定图片 ID | `id`、名称、描述、路径、状态和实际图片帧；失败返回错误结果 |
| `meme_edit` | `meme_id`：本轮已查看的图片 ID；`name`：新名称；`description`：新描述 | `ok`、当前名称、描述、路径；资料变化时重新查看 |
| `meme_disable` | `meme_id`：本轮已查看并确认的图片 ID | 成功返回 `ok=true`、`status=disabled`、当前名称、描述和路径；失败返回 `ok=false` 与错误，资料变化时重新查看 |
| `meme_send` | `meme_id`：本轮已查看并选中的图片 ID | 返回 `ok`、`sent`，成功包含图片信息、路径及本地时间 `sent_at`，格式 `YYYY-MM-DD HH:mm:ss`；失败返回 `ok=false`、`sent=false` 和错误 |

`meme_send` 只发送原图。需要文字时，模型通过正常回复输出，文字分段由 AstrBot 的「分段回复」设置控制。工具说明会提醒模型直接回应当前对话，避免额外汇报“已发送图片”。

需要只发图片时，可安装同一源中的[沉默工具](https://github.com/littleApricot/astrbot_plugin_silence)：模型确认 `meme_send` 成功后，单独调用无参数的 `silence`，结束本轮。发图结果按下节写入历史上下文。发图失败返回错误，供模型决定下一步；平台发送失败时，该轮不自动重试同一图片，避免送达状态不确定时重复发送。

## 聊天流程与历史上下文

群里的原始消息正常进入回复判断和回复流程；图片收集与识别在后台独立执行，识别结果写入图库。正式回复开始后，回复模型取得本轮临时推荐，也可主动调用搜索、查看工具，结合当前对话决定是否使用表情。

与回复判断插件配合时，图片入库后的下一条消息起，只有该次请求已被判断插件放行、正式回复开始前，才在本轮临时提示中加一句：**已收录之前聊天里发现的新表情包。** 判断模型看不到这句提醒，当前消息中新收录的图片留到后续轮次提示。未生成回复且未成功发图时保留提醒；回复模型生成完成或图片发送成功后，记录本次已提示的进度，期间又入库的新图留待后续提示。

与 LCM 配合时，插件声明系统提示、临时提示和历史投影。推荐候选与新增提示仅进入提供商的本轮输入副本；不写入后续历史，也不供回复判断或 LCM 整理。图片命名和描述的生成风格只交给识图模型，主模型通过系统区的工具说明了解操作规则。独立使用时，通用推荐提示继续随临时候选提供，具体工具用法沿用原生工具定义。

当前执行保留完整 `meme_search`、`meme_view`、`meme_send` 调用、结果及看过的图片。后续有效历史隐藏搜索和看图，成功发图转为历史附件，包含稳定图片 ID、当时名称和描述、发送时间及图片；动图最多四帧，发给 QQ 的仍是原文件。仅查看及失败发送不产生历史发图附件，修改、停用结果和正常正文保留。原图绝对路径继续由工具返回，供同主机 Wiki 上传。

回复、判断近期窗口和 LCM 摘要共用有效历史的内容表示。配套回复判断 v0.9.1 与 LCM 时，工具后的模型调用继续使用所属批次的历史快照，并追加本轮工具过程。LCM 的完整历史和摘要来源关系保留原始执行，图库的发图预览缓存在 `sent_previews` 表。模型可见时间的格式由 LCM 统一处理，原始档案保留。

没有启用新版 LCM 时，插件沿用独立的官方历史接入：先在 `library.sqlite3` 的 `tool_history_archive` 表归档，再在官方保存及读取时处理结构化表情工具记录。归档失败则保留原上下文。旧图文件缺失且无缓存时，保留图片 ID 和发送事实。

## 管理页

从 AstrBot 侧栏打开“群聊表情图库”。可以按名称、描述或 ID 搜索，筛选状态，编辑两个字段，查看原文件路径和修改记录，恢复版本，停用或重新启用图片。

右上角「识图提示词」可直接读取、编辑和保存生成提示词。保存写入插件配置并立即用于后续识图。

下载失败和首次识别失败的记录可重试；已有人修改过信息时保留修改，由管理页查看并处理。停用的图片退出搜索并禁止发送，原文件继续保留。

## 配置

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| 启用表情图库 | 开启 | 收图和模型工具总开关 |
| 新图片识别方式 | `provider` | `provider` 使用 AstrBot 模型；`codex` 使用本机 CLI 调用 Astra，仅影响新图识别及失败重试 |
| 本机 Codex 可执行文件路径 | 空 | 从 `PATH` 或 `~/.local/bin/codex` 查找，也可填完整路径 |
| 本机 Codex 识图超时秒数 | 120 | CLI 启动和 Astra 识别的总超时 |
| 收图识别模型 | 空 | 识别方式为 `provider` 时用于收图；默认使用来源会话回复模型 |
| 图片名称与描述生成提示词 | 内置识图提示词 | 可多行编辑，留空使用默认提示词；用于后续新图片识别和失败重试 |
| AstrBot 收图识别超时秒数 | 45 | `provider` 方式收图识别的单次调用超时 |
| 单张图片大小上限 | 15 MB | 超过上限时不保存 |
| 每次搜索返回的候选数量 | 5 | 最多返回 20 个候选 |

AstrBot 模型调用沿用提供商密钥，Codex 识图沿用 CLI 的 ChatGPT 登录。管理 API 通过 AstrBot 插件页面的认证桥接访问。

## 验证

在插件目录执行，`ASTRBOT_SOURCE` 指向自己的 AstrBot 源码：

```bash
ASTRBOT_SOURCE=/path/to/AstrBot
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH="$ASTRBOT_SOURCE:$PWD/.." \
  ASTRBOT_ROOT=/tmp/meme-library-test \
  "$ASTRBOT_SOURCE/.venv/bin/python" -m pytest tests -q
```
