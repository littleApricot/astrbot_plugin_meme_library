# 群聊表情图库

为 AstrBot 建立一个从群聊里成长的共享图库：第一次收到新图片就识别，生成一份统一说明；回复模型可以搜索、看图、发送，也可以结合普通群友的纠正修改同一份说明。

适配 AstrBot 4.29.x，验证目标为 4.29.1。运行数据位于 AstrBot 的 `data/plugin_data/astrbot_plugin_meme_library/`，更新插件保留图库。初次安装为空图库。

## 安装与使用

在 AstrBot 插件页安装本插件的 ZIP 或仓库。打开插件配置，启用“表情图库”；“收图与语义搜索模型”留空时使用来源会话的当前回复模型。该模型需要支持图片输入。插件不会修改旧表情插件或导入它的图片；切换使用时，关闭旧插件的收图及发送功能，避免两套同时工作。

仓库：[littleApricot/astrbot_plugin_meme_library](https://github.com/littleApricot/astrbot_plugin_meme_library)。在“添加插件源”中使用以下地址，可以安装“群聊表情图库”并在发布后检查更新；已经添加过这个源的用户沿用原源即可：

```text
https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json
```

所有启用了本插件的群聊共用一个图库。收到的图片先保存原文件，再由后台队列识别，聊天保持独立。完全相同的文件复用一个记录，配字不同的版本保留。识别认为适合用作表情的图片进入可用图库，其余在管理页显示为“未收录”。自己发送的图片不会再次收集。

与回复判断插件配合时，收图监听器先执行；即使机器人决定保持沉默，图片仍进入收集流程。回复判断 v0.4.0 支持含图消息由当前回复模型读取完整上下文判断，纯文字继续由百炼读取近期上下文判断。

## 一张图，一份说明

图片画面、配字、含义、适合或不适合的场景、群内特殊用法都写在同一个 `document` 中。SQLite 中的这一份文档是当前有效内容，管理页和模型编辑使用同一入口及版本检查。修改前的版本留在修改记录里，可恢复为新版本。

普通群友可以提供纠正，由回复模型根据实际图片和上下文决定是否采纳。模型先读取最新文档，再提交完整修订及原因。保存时检查读到的版本，避免旧内容覆盖新修改。群内特殊含义应在同一份说明里注明适用群。

## 搜索、看图与发送

回复模型按表达意图搜索候选，读取实际图片和说明，判断配字、态度、表达对象是否适合当前对话，再发送图片及可选配文。也可以纯文字回复。

自然语言搜索由配置的模型分批读取全部可用说明并选出匹配项；直接使用最新文档，修改立即影响后续搜索。搜索会产生模型调用，图库较大时需要多个批次。已有工具历史中的候选可直接复用；插件不强制每轮重新搜索。

查看图片工具返回真实图片内容。动图提供最多四张分散位置的预览帧，发送时使用原始动图。发送工具要求本轮已查看当前版本，且视觉图片已经经过一次后续模型推理；同一批并行的“查看”和“发送”会被拒绝。同一轮重复发送同一图片会被拦截。

`meme_send` 实际发送图片及配文，返回成功或失败。成功后模型应避免再重复发送相同内容。平台出错时返回 `sent=false`，该轮不会自动重试同一图片，以免部分送达后重复发送。

## 工具参数

| 工具 | 必填参数 | 返回 |
| --- | --- | --- |
| `meme_search` | `query`：想表达的含义、态度及对象 | `ok`、`candidates`；每项包含 `id`、完整 `document`、`revision`、匹配 `score` |
| `meme_view` | `meme_id`：稳定图片 ID | 文档、版本、状态与实际图片帧；失败返回错误结果 |
| `meme_edit` | `meme_id`、`document`：完整新说明、`expected_revision`：已读取的整数版本、`reason`：修订原因 | 新文档和版本；冲突要求重新读取 |
| `meme_send` | `meme_id`、`expected_revision`、`caption`：配文，纯图时填空字符串 | `ok`、`sent`；成功包含图片 ID、版本和配文 |

工具失败时返回 `ok=false` 和错误原因；`meme_view` 使用 AstrBot 支持的多模态工具结果格式。

## 历史与新增提醒

搜索、查看、编辑、发送的工具调用和结果沿用 AstrBot 正常上下文与历史机制。插件不额外清理、重写或裁剪会话历史。实际发图前的预览也由 AstrBot 正常保存，因此后续模型能引用已经使用过的图片与说明。

只有新图片进入可用图库时，在各会话的下一次模型输入里简单提示：**图库有新增表情包。** 不附带清单、描述或变化详情。模型完成回复后记录该会话已知的新增位置。修改说明、停用和恢复旧记录不增加新增计数；重新启用一张此前从未入库的图片时，作为首次入库处理。

## 管理页

在 AstrBot 的插件扩展页面打开“群聊表情图库 → library”。可以浏览缩略图、按说明或 ID 搜索、筛选处理状态、编辑统一说明、查看修改记录和恢复版本。

可用图片支持停用，停用后退出搜索并禁止发送，之后可以重新启用。下载失败和首次识别失败的记录可重试；已有人修改过说明时保留修改，由管理页查看并处理。图片文件仍留在图库数据目录，更新和重载不会清空它们。

## 配置

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| 启用表情图库 | 开启 | 收图和模型工具的总开关 |
| 收图与语义搜索模型 | 空 | 默认使用来源会话回复模型；可指定 AstrBot 中已有模型 |
| 识别和搜索超时秒数 | 45 | 单次后台识别或搜索模型调用的超时 |
| 单张图片大小上限 | 15 MB | 超过上限时不保存 |
| 每次搜索返回的候选数量 | 5 | 最多返回 20 个候选 |
| 语义搜索每批说明字符预算 | 24,000 | 模型读取说明的分批预算，不是 token 计数 |

模型的密钥沿用 AstrBot 提供商配置，插件没有独立 Key。管理 API 通过 AstrBot 插件页面的认证桥接访问。

## 验证

在 AstrBot 的 Python 环境执行，`ASTRBOT_SOURCE` 指向自己的 AstrBot 源码目录：

```bash
ASTRBOT_SOURCE=/path/to/AstrBot
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH="$ASTRBOT_SOURCE:$PWD/.." \
  ASTRBOT_ROOT=/tmp/meme-library-test \
  "$ASTRBOT_SOURCE/.venv/bin/python" -m pytest tests -q
```

隔离测试使用合成图片及记录输入的模型，覆盖跨群去重、首次识别、失败重试、统一说明修改与版本冲突、新增提醒、动图预览、管理 API，以及 AstrBot 实际工具运行器中的“返回图片 → 模型看到图片 → 发送 → 保存工具历史”。管理页在隔离服务中实际操作编辑和恢复。真实识图效果、真实模型兼容性和 QQ 发送需要在目标环境另行验证。
